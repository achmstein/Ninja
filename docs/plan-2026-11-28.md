## Trying the account by phone

variables `NINJA_PHONE_*`): nothing is sent, and only the two test numbers are
ever given a code.

- Open `https://cove.ninjapp.net/?phone-account`, add an item, press the order
  button as a guest. Number `010 0000 0001` (or `…0002`), code `482193`.
- A number that is new is asked its first and last name on the sign-in page.
- Any other number goes to the ordinary sign-in page: no code can reach it.

- **A real sender.** One more `CodeSender` in `src/keycloak-phone`. The owner
  prefers WhatsApp with the customer sending (free); it needs his Meta
  business verification and a number, and I owe him the click-by-click list.
  The no-set-up alternative is Firebase or an SMS gateway (about $0.16 a
  message to Egypt when looked up; check the live price).
- Before a real sender goes live: delete the test numbers' accounts, turn the
  web's switch on for everyone (`phoneAccountOn`), build the app with the
  define, and only then make ordering require an account and take the guest
  code out (about 40 web files and 148 server files mention guests).
- Decided: paying a bill or opening a receipt from a link stays open to
  anyone with the link.
- The web's sign-in page for a number that already has an email account does
  not join the two: an account is a number's only when the number was proved
  for it. Joining them (prove the number while signed in) is not built.
