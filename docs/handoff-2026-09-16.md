## 4. Rules and gotchas (restated from Claude's memory)

**Owner rules**
- Minimal UI, far less text: label + value + control; no helper sentences; **progressive disclosure** — every explanation is one tap away (ⓘ, expand, hover), never resident. Dialog = title + inputs + one action. Empty state = one line + action. Confirm = question in the title, Cancel/Verb, at most "Cannot be undone."
- One type scale per element on every page; tables readable (numbers end‑aligned + tabular, key column emphasised, muted secondaries, sticky header, status as colour/badge). Target: a premium, calm back‑office.
- Everything in both apps: pos_web ⇄ pos_app parity every batch (and admin where relevant).
- No dated/calendar room bookings, ever (rooms are walk‑in + 10‑minute hold). No table reservations or waitlists.
- Flat one‑click sidebar; no card grids in admin_web (StatStrip, one surface per band); real shadcn components.
- HARD RULE: services never call each other synchronously — events + local read models only; the SPA/BFF may join.
- Deliberate and simple: settle design decisions first, build the minimal thing; best practices over shortcuts.

**Tooling gotchas**
- Bash tool: long python heredocs with unicode/backslashes fail to parse — write the script to a file and run it.
- `dotnet ef migrations add … --no-build` uses the *last built* assembly: build the project first or the migration comes out empty. Sales migrations: `--project src/Sales.Infrastructure --startup-project src/Sales.API`; Branch/Catalog: `--project src/<Svc>.API`.
- OpenAPI json regenerates at `dotnet build`; then `npm run generate:api` in each SPA. It rewrites *other* services' clients with EOL‑only noise — `git checkout` any `src/api/<svc>` dir with no `git diff -w` change.
- Tests use Microsoft.Testing.Platform: `dotnet test` rejects `--filter`/`-nologo`.
- Unit‑test `TicketLine`s have Id 0 — subclass `TicketLine` to set an Id when a test moves lines.
- Forui: `FButton` default variant is `null` (there is no `.primary`); `FButton.raw` truncates; Riverpod here has no `valueOrNull` (use `.value`).
- pos_app `l10n.yaml` + `flutter gen-l10n`; client/admin web i18n is generated from the sibling Flutter ARB (`npm run generate:i18n`); pos_web `i18n.ts` is hand‑written.
- admin_web routes: adding a file under `src/routes` needs `npx vite build` (or dev) to regenerate `routeTree.gen.ts` before `tsc` passes; `vitest` type errors in `tsc -b` are pre‑existing (dev dep missing).
- TanStack column meta: `meta: { align: 'end' }` for numbers; `className/thClassName/tdClassName` for widths.
- `IsInRole` on `ClaimsPrincipal` is the ServiceDefaults extension (reads `role` claims); Owner policy = `RequireRole("Owner")`.
- Prod: postgres data is in the named volume; never prune the old anonymous volume; the classifier blocks prod writes — owner runs scripts via `!`.
